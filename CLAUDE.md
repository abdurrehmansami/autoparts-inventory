# AutoParts Inventory — project guide for Claude

Offline desktop app (inventory, sales, purchases, accounts) for a single auto parts
shop in Karachi. Replaces a 2012 Windows app ("Express Inventory"). Runs on one
Windows 10/11 PC at the shop; developed on Ubuntu. Everything must stay free/open source.

Read before larger work: [docs/PRD.md](docs/PRD.md) (what), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
(how), [docs/DB_SCHEMA.md](docs/DB_SCHEMA.md) (data), [docs/ROADMAP.md](docs/ROADMAP.md) (status).

## Stack
- Electron 44 + electron-vite 5 (Vite 7) — one codebase, Windows `.exe` + Linux AppImage/deb
- Renderer: React 19, TypeScript 5.9, Tailwind CSS 4, Radix primitives (shadcn-style components
  hand-written in `src/renderer/src/components/ui`), TanStack Query + Table, React Hook Form + Zod,
  react-router (HashRouter), i18next (English + Urdu, RTL)
- Main process: **`node:sqlite`** (built into Electron's Node 24 — no native modules to compile) wrapped by
  `src/main/db/sqlite-adapter.ts` so Drizzle ORM's sync better-sqlite3 session can drive it. Never add
  `better-sqlite3` or any other native module: it breaks building the Windows installer from Ubuntu.
- Migrations generated by drizzle-kit into `drizzle/`, applied at startup
- Tests: Vitest, run **inside Electron's Node** (`npm test`) so SQLite/Node versions match production

## Commands
| Task | Command |
|---|---|
| Run app (dev, hot reload) | `npm run dev` |
| Type check | `npm run typecheck` |
| Tests | `npm test` |
| New migration after editing schema | `npm run db:generate` |
| Linux installer | `npm run dist:linux` |
| Windows installer | `npm run dist:win` (on Ubuntu needs `wine`; else GitHub Actions) |
| Windows portable zip | `npm run dist:win:zip` (no wine needed) |

Before saying a task is done: `npm run typecheck && npm test` must pass, and UI changes must be
checked in the running app in **both English and Urdu**.

Environment gotchas
- VS Code's terminal exports `ELECTRON_RUN_AS_NODE=1`; launch the app with
  `env -u ELECTRON_RUN_AS_NODE npm run dev`, otherwise Electron starts as plain Node and crashes.
- Ubuntu 26.04: Electron's Wayland backend segfaults → scripts pass `--ozone-platform=x11`
  (only a CLI flag works; setting it from code is too late). Windows ignores the flag.
- zod 4: `.partial()` keeps field `.default()`s — patch schemas must be built from fields without
  defaults (see `src/shared/schemas/settings.ts`).
- TanStack Table caches accessor values per row; choose language-dependent text in `cell`, not the accessor.

## Layout
```
src/shared/      types, IPC contract, zod schemas, money/format helpers (imported by main AND renderer — no Node/DOM APIs here)
src/main/        Electron main: window, db/, services/ (business logic), ipc/ (handlers), print/
src/preload/     exposes window.api.invoke — nothing else
src/renderer/src app/, components/{ui,layout}/, features/<module>/, i18n/{en,ur}.json, lib/
drizzle/         generated SQL migrations (commit them; never edit an applied one)
docs/            PRD, architecture, schema, roadmap
```

## Non-negotiable rules
1. **Money is integer paisa** (`1 PKR = 100 paisa`) everywhere: DB, IPC, state. Convert only at the
   edges with `src/shared/money.ts` (`toPaisa`, `formatMoney`). Never use floats for money math.
2. **Stock changes only through `src/main/services/stock.ts`** (`recordMovement`). It writes a
   `stock_movements` row and updates the cached `products.stock_qty` in the same transaction.
   Never `UPDATE products SET stock_qty` anywhere else.
3. **Every multi-row write is one transaction** (`db.transaction(...)`). A sale = header + items +
   stock movements + ledger + cash-book rows, all or nothing.
4. **Posted documents are never deleted.** Cancel them (status `cancelled`) and write reversing
   movements/entries. Masters (products, parties) are deactivated (`is_active = 0`), not deleted, once used.
5. **Business logic lives in `src/main/services`**, not in IPC handlers or React. Handlers only
   validate input (zod) and call a service. Renderer never touches SQL.
6. **Every user-visible string goes through i18n** (`t('key')`) with keys in BOTH `en.json` and
   `ur.json`. Errors thrown from main use `AppError(code)` where `code` is an i18n key under `errors.*`.
7. **RTL-safe styling**: use logical Tailwind utilities (`ms-* me-* ps-* pe-* start-* end-* text-start
   text-end border-s border-e`). Never `ml/mr/pl/pr/left/right/text-left/text-right`. Numbers, part
   numbers and phone numbers are wrapped in `dir="ltr"` / class `num`.
8. **IPC is typed end-to-end**: add the channel to `src/shared/ipc-contract.ts` first, then the zod
   schema, handler and renderer hook. All handlers except `auth:*` require a logged-in session.
9. Security: `contextIsolation: true`, `nodeIntegration: false`, no `remote`, preload exposes only
   `invoke`. No network calls — the app is fully offline.
10. Keep it keyboard-friendly: counter staff use Enter/Tab/F-keys, not the mouse. Forms submit on
    Enter, F2 = new sale, F3 = find product, Esc closes dialogs.

## Conventions
- Files: `kebab-case.ts`; React components `PascalCase` exported by name; one feature per folder
  under `features/` with `api.ts` (query hooks), `*-page.tsx`, `*-form.tsx`.
- DB columns `snake_case`; TS fields `camelCase` (Drizzle maps them).
- Dates stored as ISO `YYYY-MM-DD` text for business dates, `datetime('now')` text for timestamps.
  Displayed as `DD-MM-YYYY`.
- Document numbers come from `services/sequence.ts` (`S-000001`, `P-000001`, `Q-…`, `RV-…`, `PV-…`).
- Quantities are integers in the product's unit. Fractional sales → use a smaller unit (e.g. foot).
- Tests sit next to code as `*.test.ts`; service tests use `createTestDb()` (in-memory, migrated).
